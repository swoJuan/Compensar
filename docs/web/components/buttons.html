2.1 — Botones

Los botones permiten a los usuarios ejecutar acciones dentro de la interfaz. Son uno de los componentes más importantes del sistema; guían la interacción, la toma de decisiones y la jerarquía visual de cada pantalla.

2.1.3 Tipos de botón

  
El sistema define cuatro tipos según su nivel de importancia en la interfaz.

  


    

      

        
      

      
Primario

      
Acción principal de la pantalla. La más visible y de mayor jerarquía.

      

        Usa para: confirmar acciones, continuar procesos, enviar formularios.

        Regla: solo uno por vista.
      

    


    

      

        
      

      
Secundario

      
Apoyo para acciones menos relevantes o alternativas al primario.

      

        Usa para: acciones alternativas, navegación secundaria.
      

    


    

      

        
      

      
Terciario

      
Baja prioridad y mínima carga visual. Altura 32 px.

      

        Usa para: acciones complementarias, acciones dentro de cards o tablas.
      

    


    

      

        
      

      
Especial

      
Acciones estratégicas de negocio para conversión y adquisición.

      

        Usa para: afiliarse a un plan, solicitar asesoría, iniciar afiliación.

        Regla: máximo uno por vista; no reemplaza al primario en flujos transaccionales.

          Input
          Tipo
          Default
          Descripción
        

      
      
        

          tipo
          'primario' | 'secundario' | 'terciario' | 'especial'
          'primario'
          Variante visual del botón. Determina colores, tamaño y jerarquía.
        

        

          label
          string
          ''
          Texto visible del botón. Puede omitirse si se usa icono con ariaLabel.
        

        

          iconLeft
          string?
          undefined
          Nombre de icono Material Symbols Rounded que aparece a la izquierda del texto.
        

        

          iconRight
          string?
          undefined
          Nombre de icono Material Symbols Rounded que aparece a la derecha del texto.
        

        

          buttonType
          'button' | 'submit' | 'reset'
          'button'
          Tipo HTML nativo del elemento <button>. Usar 'submit' en formularios.
        

        

          disabled
          boolean
          false
          Deshabilita el botón. Aplica estilos disabled y bloquea el evento clicked.
        

        

          ariaLabel
          string?
          undefined
          Requerido cuando el botón no tiene texto visible (solo icono). Para lectores de pantalla.
        

        

          clicked
          EventEmitter<void>
          —
          Output que emite al hacer clic. No emite cuando disabled es true.

Accesibilidad

  

    

      
Interacción y teclado

      
Todos los botones son accesibles con Tab y activables con Enter o Espacio.

      
El estado :focus-visible siempre debe ser visible y consistente.

      
Los botones deshabilitados llevan disabled + aria-disabled="true".

      
Área táctil mínima de 44×44px en mobile. La altura de 48px ya lo garantiza.

    

    

      
Contenido y texto

      
Primera letra en mayúscula, resto en minúscula. Ejemplo: "Mis citas".

      
Botones solo-icono requieren ariaLabel descriptivo. Los iconos llevan aria-hidden="true".

      
No depender solo del color para comunicar estado. Complementar con texto o icono.

      
Usar texto claro y directo. Evitar términos ambiguos como "Clic aquí".

    

    

      
Contraste (WCAG 2.1)

      
Primario: texto blanco sobre gradiente naranja → 4.8:1 ✓ AA.

      
Secundario: naranja #ff6600 sobre blanco → 3.2:1 (texto grande) ✓.

      
Alto contraste: amarillo #ffff00 sobre negro → 19.6:1 ✓ AAA.

      
Disabled: gris neutro → no necesita contraste AA (estado inactivo por norma).

    

    

      
Jerarquía y uso

      
Solo un botón Primario por vista o flujo principal.

      
No usar múltiples botones Especial en la misma pantalla.

      
Mantener consistencia en estados hover, focus y active en todos los modos.

      
Validar componentes críticos en modo High Contrast antes de publicar.
